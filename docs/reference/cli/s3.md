# S3 storage

The `yerd s3` commands manage the buckets in Yerd's local S3 storage service,
`versitygw`, and print the endpoint and access keys S3 clients need. To install,
start, or stop the gateway itself, see [Services](./services); the [S3 storage
guide](../../guide/services#s3-storage-versitygw) covers the model and the
Laravel setup.

::: tip The gateway must be running
The bucket commands talk to the gateway over the S3 API, so `versitygw` must be
installed and started first (`yerd service start versitygw`). `yerd s3 creds`
only needs it installed. None of the commands need elevation.
:::

## Commands

| Command | Description |
| --- | --- |
| `yerd s3 buckets` | List the buckets, sorted by name. |
| `yerd s3 create-bucket <NAME>` | Create a bucket. |
| `yerd s3 drop-bucket <NAME>` | Delete a bucket and every object in it (irreversible). |
| `yerd s3 bucket-stats <NAME>` | Show a bucket's object count and total size. |
| `yerd s3 creds [--show-secret]` | Show the endpoint and access key; `--show-secret` also prints the secret key. |

```sh
yerd s3 create-bucket user-uploads
yerd s3 buckets
yerd s3 bucket-stats user-uploads
yerd s3 creds --show-secret
yerd s3 drop-bucket user-uploads
```

Example output:

```text
$ yerd s3 bucket-stats user-uploads
1284 objects, 312.4 MiB (327577190 bytes)

$ yerd s3 drop-bucket user-uploads
deleted bucket - 1284 objects removed

$ yerd s3 creds
endpoint: http://127.0.0.1:7070
access key: yerd_7Kq2XH9PmA
secret key: (hidden - pass --show-secret)
```

`buckets` prints one name per line, or `no buckets`. `create-bucket` prints `ok`.

## Bucket names

`create-bucket` checks the name against the S3 rules before anything is sent to
the gateway. A name must:

- be **3 to 63 characters** long;
- contain only lowercase letters, digits, hyphens (`-`) and dots (`.`);
- start and end with a letter or digit;
- not contain two dots in a row (`..`);
- not be formatted as an IP address (`192.168.5.4`);
- not start with `xn--`, `sthree-` or `amzn-s3-demo-`, and not end with
  `-s3alias`, `--ol-s3`, `.mrap`, `--x-s3` or `--table-s3`.

`drop-bucket` and `bucket-stats` take the name of a bucket that already exists.

## Deleting a bucket

`drop-bucket` lists the bucket and deletes its objects one at a time until it is
empty, then deletes the bucket, and reports how many objects it removed. There
is no confirmation prompt and no undo. On loopback this is quick for a few
thousand objects, but a very large bucket takes a while.

## Credentials

`creds` reads the access keys Yerd generated for this install (creating them if
the gateway has never started) from `<state>/services/versitygw/credentials`.
The endpoint uses the port the gateway is listening on, or the configured port
while it is stopped. The secret key is printed only with `--show-secret`, and
in `--json` output the `secret_key` field is omitted without it.

## JSON output

With `--json`, each command prints the daemon's response as pretty JSON instead
(`create-bucket` prints `{"type": "ok"}`):

```sh
yerd --json s3 bucket-stats user-uploads
```

```json
{
  "type": "bucket_stats",
  "objects": 1284,
  "bytes": 327577190
}
```

| Command | Response `type` | Fields |
| --- | --- | --- |
| `buckets` | `buckets` | `buckets`: array of `{ "name": … }` |
| `bucket-stats` | `bucket_stats` | `objects`, `bytes` |
| `drop-bucket` | `bucket_dropped` | `objects_removed` |
| `creds` | `s3_credentials` | `endpoint`, `access_key`, and `secret_key` only with `--show-secret` |

## Errors

The daemon errors below exit with code `1`; see [Exit codes](./#exit-codes) for
the others.

| Situation | Error code | Message |
| --- | --- | --- |
| `versitygw` is not installed | `not_found` | `no S3 (versitygw) version installed`, followed by the install command |
| The gateway is stopped (bucket commands) | `internal` | `start S3 (versitygw) first - managing buckets needs the running gateway: yerd service start versitygw` |
| Invalid bucket name | `invalid_path` | the rule it breaks, e.g. `bucket names must not contain two dots in a row` |
| The bucket already exists | `already_exists` | `a bucket called <name> already exists` |
| The bucket doesn't exist | `not_found` | `no bucket called <name>` |
| Any other gateway error | `internal` | the gateway's S3 error message |
